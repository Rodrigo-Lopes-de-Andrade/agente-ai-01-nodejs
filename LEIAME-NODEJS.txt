  Tres caminhos eram possiveis. Este projeto escolheu o primeiro:

  A) TUDO EM NODE.JS (escolhido). Um unico projeto Next.js: telas em React,

     mudanca nos agentes, mas dois deploys, CORS para configurar e um
     servidor para cuidar -- justamente o que a Vercel evita.

  A licao que sobrevive a troca de linguagem e a mesma do capitulo: os
  agentes NAO sabem quem e o LLM. Trocar de provedor e trocar o objeto
  passado em "model:". Em lib/dsa-agentes.ts isso fica ainda mais visivel.

3. INSTALAR O NODE.JS
--------------------------------------------------------------------------------

  O Node.js e para o JavaScript o que o interpretador python e para o Python:
  o programa que executa o codigo fora do navegador. O projeto exige a versao
  22 ou mais nova (o yahoo-finance2 e o Next.js 16 nao rodam em versoes
  anteriores).

  O jeito recomendado no WSL/Linux/macOS e o nvm (Node Version Manager) -- o
  equivalente ao "uv python install": permite ter varias versoes lado a lado
  e trocar por projeto, sem sudo.

      curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
      source ~/.bashrc          # ou ~/.zshrc
      nvm install 24
      nvm use 24

  Windows sem WSL: baixe o instalador em https://nodejs.org (versao LTS).

  Conferir:

      node --version            # v22.x ou v24.x
      npm --version             # vem junto com o Node

  O npm e o gerenciador de pacotes (o pip/uv do JavaScript). Ele ja vem com
  o Node; nao ha nada mais para instalar.

4. CRIAR O AMBIENTE DO PROJETO
--------------------------------------------------------------------------------

      cd ~/projects/dsa/12-Projeto-NodeJS
      npm install

  So isso. O npm le o package.json, baixa os pacotes para a pasta
  node_modules/ e grava as versoes exatas em package-lock.json.

  A correspondencia com o mundo Python:

      pyproject.toml    ->  package.json        (o que o projeto precisa)
      uv.lock           ->  package-lock.json   (a foto exata do instalado)
      .venv/            ->  node_modules/       (os pacotes em si; ~400 MB)
      uv sync           ->  npm install
      uv add pacote     ->  npm install pacote
      uv run comando    ->  npm run comando     (scripts do package.json)

  As duas pastas pesadas (.venv e node_modules) estao no .gitignore: nunca
  vao para o GitHub, sao recriadas a partir dos arquivos de lock.

  4.1 O package.json EXPLICADO (o JSON nao aceita comentarios, entao eles
      ficam aqui)

  "scripts" -- os comandos do projeto. 'npm run <nome>' executa cada um:
      dev        next dev          servidor de desenvolvimento, recarrega ao salvar
      build      next build        compila para producao (e o que a Vercel roda)
      start      next start        serve o que o build gerou (producao local)
      typecheck  tsc --noEmit      so confere os tipos, sem gerar nada
      modelos    node ... dsa_lista_modelos.mjs   lista modelos validos

  "dependencies" -- o que o app usa para rodar:
      next, react, react-dom       o framework e a biblioteca de telas
      ai                           o AI SDK da Vercel (o phidata daqui)
      @ai-sdk/groq, @ai-sdk/openai, @ai-sdk/anthropic, @ai-sdk/xai
                                   um pacote por provedor de LLM
      @ai-sdk/openai-compatible    para o Ollama, que fala o protocolo da OpenAI
      zod                          descreve os parametros das ferramentas
                                   (o que os type hints faziam no phidata)
      yahoo-finance2               cotacoes do Yahoo (o yfinance daqui)
      plotly.js-finance-dist-min   o Plotly, versao JS, so com os graficos
                                   de financas (1,2 MB em vez de 4,5 MB)
      react-markdown, remark-gfm   desenham Markdown com tabelas (st.markdown)

  "devDependencies" -- so para desenvolver, nao vao para o app final:
      typescript                   o compilador que confere os tipos
      @types/node, @types/react, @types/react-dom, @types/plotly.js
                                   as "assinaturas de tipo" de cada biblioteca

  "engines": { "node": ">=22" } -- avisa (e a Vercel obedece) qual Node usar.

  4.2 O QUE E O TYPESCRIPT

  JavaScript com anotacoes de tipo, como os type hints do Python
  (def f(ticker: str) -> DataFrame). A diferenca: o TypeScript CONFERE os
  tipos antes de rodar (npm run typecheck), entao "chamei .close mas o campo
  se chama .fechamento" aparece no editor, nao na tela do cliente. Os
  arquivos .ts (logica) e .tsx (telas, com JSX) sao TypeScript; o Next.js os
  compila sozinho.

6. CHAVES DE API (.env)
--------------------------------------------------------------------------------

  Igual a versao Python: o arquivo .env na raiz da pasta guarda as chaves e
  esta no .gitignore. Se voce ja tem o .env da versao Python, ELE SERVE SEM
  MUDAR NADA -- as variaveis sao as mesmas (GROQ_API_KEY, GROQ_MODEL, ...).
  Se nao tem, copie o modelo:

      cp .env.example .env
      nano .env             # cole as chaves

  O que mudou por dentro: nao ha load_dotenv(). O Next.js le o .env sozinho
  ao iniciar e cada linha vira process.env.NOME no servidor. Duas regras:

  - So o SERVIDOR enxerga o .env. O navegador nao. E assim de proposito.
  - Variaveis com prefixo NEXT_PUBLIC_ SAO enviadas ao navegador. Nenhuma
    chave deve ter esse prefixo, jamais.

  Mudou o .env? Reinicie o 'npm run dev' (Ctrl+C e de novo): ele e lido na
  partida, como o Streamlit.

  Na Vercel nao existe .env: as chaves entram pelo painel do projeto
  (secao 9.3). Os nomes sao os mesmos.

  Onde pegar cada chave e como o app escolhe o provedor: secao 6 do
  LEIAME.txt -- vale tudo igual. Para ver os modelos validos da sua conta:

      npm run modelos

8. COMO O APP FUNCIONA POR DENTRO (o caminho de uma analise)
--------------------------------------------------------------------------------

  NAVEGADOR (app/page.tsx)                SERVIDOR (app/api/*)
  --------------------------------        ----------------------------------
  pagina abre
    GET /api/provedores  ------------->   le o .env, pergunta ao Ollama,
                         <-------------   devolve [{apelido, modelo}, ...]
  monta a caixa "Escolha o LLM"
  usuario digita MSFT, clica Analisar
    GET /api/dados?ticker=MSFT ------->   yahoo-finance2.chart(6 meses)
                         <-------------   candles + SMA_20 + EMA_20 (JSON)
  desenha os 4 graficos (Plotly)          [ticker invalido: 404, para aqui]
  mostra "Os Agentes de IA estao analisando..."
    POST /api/analisar {ticker,provedor}> monta o time para o provedor:
                                            lider -> transfer_task_to_* ->
                                            agente financeiro / busca web ->
                                            ferramentas (Yahoo, DuckDuckGo)
                         <-------------   { analise: "...markdown..." }
  desenha a analise (react-markdown)      [erro do LLM: 429/502 + explicacao]

  Duas diferencas de experiencia em relacao ao Streamlit, ambas para melhor:
  os graficos aparecem em ~1 s, enquanto o LLM ainda trabalha; e se o LLM
  falhar, os graficos continuam na tela (o st.stop() apagava tudo).

  Sobre o tempo: uma funcao serverless tem limite de duracao. A rota
  app/api/analisar/route.ts declara 'maxDuration = 300' (segundos), o teto do
  plano Hobby da Vercel. Uma analise leva 30-90 s; cabe com folga.

9. DEPLOY NA VERCEL (PASSO A PASSO)
--------------------------------------------------------------------------------

  A Vercel e a empresa que faz o Next.js, e a publicacao de um projeto
  Next.js la e o caminho "sem atrito": ela le o repositorio no GitHub, roda
  'npm install' e 'npm run build', publica em https://SEU-PROJETO.vercel.app
  com HTTPS pronto, e republica a cada 'git push'. Nao ha servidor para
  cuidar, nao ha systemd, nao ha porta para abrir.

  9.1 CONTA E REPOSITORIO

  - Conta gratuita em https://vercel.com ("Continue with GitHub").
  - O codigo precisa estar num repositorio GitHub. Esta pasta AINDA NAO e
    um repositorio git (a versao Python vive em outro, agente-ai-01). Crie
    um novo:

        cd ~/projects/dsa/12-Projeto-NodeJS
        git init
        git add -A
        git commit -m "Versao Node.js (Next.js) do capitulo 12"
        gh repo create agente-ai-01-nodejs --public --source=. --push
        # ou: crie o repositorio no site do GitHub e siga o 'git remote add'
        #     que ele mostra, seguido de 'git push -u origin main'

    Confira ANTES do push que 'git status' nao lista .env, .venv nem
    node_modules: o .gitignore ja cuida disso, mas olhar nao custa.
    O .env.example (sem valores) VAI junto, de proposito.

  9.2 IMPORTAR O PROJETO (no navegador)

  1) https://vercel.com/new  (ou painel > "Add New..." > "Project")
  2) "Import Git Repository" > escolha agente-ai-01-nodejs.
  3) Na tela de configuracao, confira:
         Framework Preset    Next.js          (detectado sozinho)
         Root Directory      ./               (a raiz do repositorio)
         Build Command       next build       (padrao; nao mexa)
         Node.js Version     22.x ou 24.x     (respeita o "engines")
  4) Abra "Environment Variables" e adicione as chaves (9.3) AGORA, antes
     do primeiro deploy -- senao o app sobe com "Nenhum motor de IA".
  5) "Deploy". A primeira construcao leva 1-2 minutos. Ao terminar, clique
     na URL, digite MSFT e clique em Analisar.

  9.3 VARIAVEIS DE AMBIENTE: AS CHAVES NA NUVEM

  Painel do projeto > Settings > Environment Variables. Uma por linha, com
  os MESMOS nomes do .env (sem aspas no valor):

        GROQ_API_KEY      gsk_...
        GROQ_MODEL        openai/gpt-oss-120b
        OPENAI_API_KEY    sk-...
        OPENAI_MODEL      gpt-4o-mini

  Marque os ambientes Production e Preview. Nao coloque OLLAMA_HOST nem
  OLLAMA_MODEL: nao ha Ollama na Vercel, e o app ja esconde a opcao quando
  nao encontra o servidor (o teste de 1,5 s em dsaOllamaDisponivel).

  IMPORTANTE: variavel salva DEPOIS de um deploy so vale para o PROXIMO
  deploy. Mudou uma chave? Deployments > (o ultimo) > "..." > Redeploy.

  Por que o app nao precisou mudar: process.env.GROQ_API_KEY encontra a
  variavel do painel do mesmo jeito que encontrava a do .env. E o mesmo
  motivo pelo qual o os.getenv() do Python funcionava no Community Cloud.

  9.4 ATUALIZAR O APP DEPOIS

  Todo push no branch main republica em cerca de um minuto:

        git add -A
        git commit -m "descricao da mudanca"
        git push

  Push em OUTRO branch gera um "Preview Deployment" com URL propria -- da
  para testar uma mudanca antes de leva-la ao main. Mudou dependencias
  ('npm install pacote')? O package-lock.json muda junto e vai no commit.

  9.5 ALTERNATIVA: PELA LINHA DE COMANDO (Vercel CLI)

  Serve para publicar sem passar pelo GitHub (bom para um teste rapido):

        npx vercel login                 # abre o navegador para autorizar
        npx vercel                       # liga a pasta a um projeto e faz um deploy de preview
        npx vercel env add GROQ_API_KEY production   # pede o valor no terminal
        npx vercel --prod                # deploy de producao
        npx vercel logs <url-do-deploy>  # logs da funcao

  O 'vercel' cria a pasta .vercel/ (ja no .gitignore) com a ligacao ao
  projeto. 'npx vercel env pull .env.local' baixa as variaveis do painel
  para um arquivo local -- o Next.js tambem le .env.local.

  9.6 LOGS (onde foi parar o terminal)

  Painel do projeto > aba "Logs" (ou "Observability"). E ali que aparecem
  as linhas "[multi_ai_agent] Running: ..." de cada analise -- o mesmo que
  voce ve no terminal do 'npm run dev'. Filtre pela rota /api/analisar.

  9.7 LIMITES DO PLANO HOBBY (gratuito) -- conferidos em setembro de 2026

  - Duracao maxima de uma funcao: 300 s (padrao e teto). A rota de analise
    ja pede exatamente isso. O plano Pro vai a 800 s.
  - Memoria: 2 GB. Tamanho da funcao: 250 MB. Este projeto usa uma fracao.
  - Resposta de uma funcao: ate 4,5 MB. A analise tem alguns KB.
  - Regiao padrao das funcoes: iad1 (Virginia, EUA). Otimo para Groq,
    OpenAI e Yahoo, que tambem estao nos EUA.
  - O plano Hobby e para uso PESSOAL e nao comercial, pelos termos da
    Vercel. Para cobrar de um cliente (a "monetizacao" do titulo do
    capitulo), o plano e o Pro (por membro/mes) -- confira os termos e
    precos atuais em https://vercel.com/pricing antes de fechar negocio.
  - Nao ha Ollama nem GPU: um provedor em nuvem (Groq, OpenAI...) e
    obrigatorio, como no Community Cloud.

  9.8 E A AWS EC2 DA AULA?

  Continua possivel, e o caminho e ate mais simples que o do Streamlit:
  na instancia, instale o Node (secao 3), 'git clone', 'npm install',
  'npm run build' e rode 'npm run start' como servico systemd (mesma
  receita da secao 9.7 do LEIAME.txt, trocando o ExecStart por
